# Regex Tab Keeper 実装解説

## 目的

Regex Tab Keeper は、URL の正規表現で「残すタブ」を指定する Chrome 拡張機能です。有効なルールのいずれかに一致したタブは残し、一致しないタブを削除候補にします。対象は、拡張機能からアクセスできるすべての Chrome ウィンドウです。

タブを閉じる操作は元に戻せない場合があるため、画面の操作性だけに頼らず、バックグラウンド処理でも実行条件を検証しています。

## 構成

|ファイル|責務|
|---|---|
|`manifest.json`|Manifest V3、ポップアップ、サービスワーカー、`storage` と `tabs` の権限を宣言します。|
|`icons/`|ツールバーと拡張機能管理画面で使うPNGアイコンを格納します。|
|`core.js`|ルールの検証・正規化、正規表現による照合、タブ分類、設定のインポート・エクスポートを担当します。|
|`popup.js`|ルール編集、Chrome ローカルストレージへの保存、プレビュー表示、確認ダイアログ、設定移行を担当します。|
|`background.js`|全タブを取得し、再分類した結果に基づいて削除を実行します。|
|`test/`|Node.js の標準テストで、コア処理、バックグラウンド処理、マニフェストを検証します。|

`popup.html` は `core.js` を先に読み込むため、ポップアップとサービスワーカーは同じルール処理を共有できます。サービスワーカーでは `importScripts("core.js")` で同じファイルを読み込みます。

## ルールのライフサイクル

ルールは次の形式で `chrome.storage.local` に保存します。

```json
{
  "enabled": true,
  "rules": [
    {
      "id": "rule-id",
      "pattern": "^https://docs\\.example\\.com/",
      "flags": "i",
      "enabled": true
    }
  ]
}
```

`core.js` の `validateRuleInput` は、空文字、500文字を超えるパターン、不正または重複したフラグ、JavaScript の `RegExp` としてコンパイルできない値を拒否します。保存済みの壊れたルールは通常読み込み時に除外します。一方、JSON インポートは `strict` モードで扱うため、不正なルールを含むファイル全体を拒否します。

ルール照合時は `matchesAnyRule` が各正規表現の `lastIndex` をゼロに戻します。これにより、`g` または `y` フラグ付きの正規表現でも、前のタブの照合状態が次のタブに影響しません。

## プレビューから削除まで

処理の流れは次のとおりです。

1. ポップアップが `getPreview` メッセージを送ります。
2. サービスワーカーが `chrome.tabs.query({})` を呼び、すべてのアクセス可能なウィンドウのタブを取得します。
3. `classifyTabs` が各タブを「残す」と「閉じる」に分類し、ポップアップに返します。
4. 利用者が件数とURLを確認し、確認ダイアログで了承すると、ポップアップが `closeNonMatchingTabs` を送ります。
5. サービスワーカーはタブ一覧と設定を改めて取得します。拡張機能が無効、または有効ルールが0件なら、この時点で削除を拒否します。
6. 最新の分類結果から数値のタブIDだけを取り出し、`chrome.tabs.remove` に渡します。

手順5で再取得するため、プレビュー表示後にタブや設定が変わっても、古いプレビューのIDをそのまま削除しません。ただし、実行時点で条件に一致しないタブは、開かれているウィンドウをまたいで閉じられます。実行前には必ずプレビューを確認してください。

## URL の扱い

通常は Chrome の `tab.url` を使います。読み込み中などで URL がまだ確定していない場合は `tab.pendingUrl` を代わりに使います。どちらも取得できないタブはどのルールにも一致しないため、削除候補になります。

拡張機能からアクセスできるタブだけが対象です。シークレットモードのタブは、Chrome 側でこの拡張機能のシークレットモード実行を許可している場合にのみ、Chrome の権限モデルに従って扱われます。

## テストと継続的インテグレーション

依存パッケージを使わず、Node.js 20 以上で次を実行します。

```bash
npm ci
npm run check
```

`npm run check` は `core.js`、`background.js`、`popup.js` の構文検査と `node --test` を実行します。バックグラウンド処理のテストでは Chrome API をモックし、複数ウィンドウのタブを取得すること、有効ルールが0件なら削除しないこと、別ウィンドウの不一致タブを削除対象に含めることを確認します。

GitHub Actions は pull request と `main` への push で同じ検証を実行します。
